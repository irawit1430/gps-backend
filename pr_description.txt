**What**
Dynamically checked the P2002 target field in `/api/schools/:schoolId/students` to ensure error message accurately reflects which unique constraint failed.

**Why**
When a parent email unique constraint violation occurred (e.g., during parent auto-creation race conditions or similar DB clashes), the system hardcoded the error message to say "RFID Tag is already assigned". This misled users to debug the RFID rather than the parent email.

**Verification**
- Verified using test reproduction script simulating `email` unique constraint violation.
- Full test suite passes.
- Pre-commit checks passed.

**Result**
The backend now correctly returns "Email address is already in use." when the email constraint is violated, and continues to return the RFID error when the RFID constraint is violated.
